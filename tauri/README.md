# Прототип Game Goal на Tauri

Проверка, стоит ли переводить программу с Electron на Tauri. Здесь пока только виджет: те же `widget.html`,
`common.css`, `common.js` и `logic.js`, а вместо `preload.js` тонкий мост `shim/api-tauri.js`. Данные не
записываются, настройки и меню не работают. Читается тестовый профиль из `GAME_GOAL_PROFILE` или встроенные
демо-данные; настоящие данные прототип не трогает.

## Сборка

Нужны Rust (rustup, MSVC) и компилятор C++ из Visual Studio.

```bash
npm install
npm run build
```

`sync-web.mjs` собирает папку `web` из файлов программы, exe получается в `src-tauri/target/release/game-goal.exe`.

## Замеры (Windows 11, 2026-11-08)

Демо-данные, виджет висит 20 секунд без действий. Память — частная (private) по всем процессам программы,
включая процессы браузерного движка.

| | Размер | Память с GPU | Память без GPU |
|---|---|---|---|
| Electron 44 | 367 МБ рантайма | 189 МБ | 113 МБ |
| Tauri 2 (WebView2) | 3 МБ exe | 200 МБ | 122 МБ |

- Память почти одинаковая: в обоих случаях это Chromium. Больше всего ест GPU-процесс (87–103 МБ).
  Без аппаратного ускорения (`--disable-gpu`) он сжимается до ~12 МБ, а виджет выглядит так же,
  углы окна остаются прозрачными, в покое — 0,3–0,5 % одного ядра.
- Выигрыш Tauri — размер (3 МБ вместо 367 МБ, установщику не нужно качать Electron) и сборка под macOS и Linux
  из того же кода. По памяти на Windows выигрыша нет.
